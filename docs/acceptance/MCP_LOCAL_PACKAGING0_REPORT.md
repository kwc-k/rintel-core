# MCP-LOCAL-PACKAGING0 acceptance

**Verdict: PASS / FROZEN for the isolated candidate branch.** This is not a claim that `main` or the public v0.1.0 release already includes the change.

The implementation starts the existing MCP server through `./rintel mcp` or the installed `rintel mcp` command. It uses the same `server.settings` and `server.deps.build_store` path as `./rintel serve`, defaulting to platform SQLite and honoring the existing `RINTEL_DATA_HOME` and advanced PostgreSQL configuration. The undeclared standalone `pgserver` fallback is gone. The default exposure is the eleven-tool read preset; `--preset design-execute` explicitly adds seven existing lifecycle/workspace tools. `RINTEL_MCP_TOOLS` remains an explicit custom exposure contract. `tools/list` is authoritative.

Independent review found and reproduced three defects in the earlier candidate: disguised file resource URIs could reach an unintended file-read path, malformed `tools/call` arguments produced an internal error, and published repository responses could receive the frozen lane's misleading `r0` evidence revision. A separate fix branch closed all three, including the error-response variant, with negative tests through both `tools/call` and `resources/read`. The independent reviewer re-ran and accepted the bounded diff; the original PR head was not silently treated as accepted.

The same archive bytes were extracted into fresh temporary directories on macOS arm64 and Linux x86_64. On each platform, `./install.sh` completed and all ten focused tests passed.
