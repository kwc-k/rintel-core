# MCP-LOCAL-PACKAGING0 acceptance

**Verdict: PASS / FROZEN for the isolated candidate branch.** This is not a claim that `main` or the public v0.1.0 release already includes the change.

The implementation starts the existing MCP server through `./rintel mcp` or the installed `rintel mcp` command. It uses the same `server.settings` and `server.deps.build_store` path as `./rintel serve`, defaulting to platform SQLite and honoring the existing `RINTEL_DATA_HOME` and advanced PostgreSQL configuration. The undeclared standalone `pgserver` fallback is gone. The default exposure is the eleven-tool read preset; `--preset design-execute` explicitly adds seven existing lifecycle/workspace tools. `RINTEL_MCP_TOOLS` remains an explicit custom exposure contract. `tools/list` is authoritative.

The public source archive at implementation commit `c65d239717af211551889e7a6b80613b0f93c42f` had SHA-256 `fb8681cb4be96e28677ee1818e66f4da718bc75691d33cb5608808a09dab5b16`. The same archive was extracted into fresh temporary directories on macOS arm64 and Linux x86_64. On each platform, `./install.sh` completed, `./rintel doctor --json` reported MCP `READY` with SQLite, and all ten focused tests passed after installing locked test dependencies. The tests start both the wrapper and installed CLI without `PYTHONPATH`, index a real Git repository with Python and C files, and follow symbol → CALL topology → evidence → exact SourceSpan/source. A live `serve` process and a live MCP process returned the same repository, snapshot, selected node span and provenance; the already-running MCP process also observed a later HTTP registration/index.

Failures were tested: empty datastore bootstrap; unknown and unindexed repositories; invalid argument type and URI; unexposed tools/resources; stale and deleted source; MCP restart. Published-repository source reads are bounded to a registered repository and published snapshot. The published graph projection does not infer completeness, static truth or resolution from mere presence, and tutorial/Agent claims are not promoted. `initialize` still returns the single contract in `src/rintel/mcp/instructions.py`. No tool for arbitrary shell, canonical publication, approval impersonation or unrestricted merge was added.

Machine-readable gate decisions, the nonblocking issue register, and the documentation handoff are in `analysis_tournament/mcp_local_packaging0/`. The historical full backend suite was not claimed as PASS: an earlier targeted source-workspace test expected a frozen FAC lane artifact absent from the public archive. That is recorded separately from the real published-Store path, which passed on both platforms. One transient job-poll 404 is retained as an unconfirmed, nonblocking observation rather than attributed to MCP.
